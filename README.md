# Wither Spotify Widget

Персональный Spotify-виджет для OBS. Главная страница — **панель подключения**; после авторизации она выдаёт **готовую ссылку OBS**, которая сразу показывает текущую композицию без входа в Spotify внутри OBS.

Доступные функции: название и исполнитель, таймер, прогресс, обложка и размытый фон (когда доступны), анимированная смена песни, автоматическое скрытие на паузе.

### Для тебя и друзей

После того как серверная часть установлена, **главная страница** показывает встроенный демопросмотр виджета, статус Spotify, готовый OBS-URL и настройки показа треков. Ссылка просмотра скрыта по умолчанию, чтобы случайно не попасть на скриншот стрима.

Владелец может [создать одноразовое приглашение](worker/README.md#приглашения-друзьям-и-режим-владельца). Другу потребуется только перейти по ссылке, авторизоваться через Spotify и скопировать собственный OBS-URL. Для приглашений нужны таблицы `invites` и `admin_sessions` в Cloudflare D1; аккаунт друга предварительно разрешается в Spotify Developer. Владелец один раз вводит `PAIRING_KEY` и получает **ограниченный доступ на 90 дней для создания приглашений**, который можно отозвать.

## Как пользоваться

1. **Один раз** разверни Cloudflare Worker с D1 по [инструкции worker/README.md](worker/README.md). Это облачная функция, не приложение на твоём ПК.
2. Добавь адрес Worker `https://...workers.dev/oauth/callback` в Redirect URIs Spotify Developer App.
3. Открой **[главную страницу](https://witheroffic.github.io/spotify-widget-pkce/index.html)**.
4. Вставь адрес Worker и `PAIRING_KEY`, нажми **«Подключить Spotify»** и разреши доступ.
5. Главная страница выдаст **индивидуальную OBS-ссылку**. Скопируй её и добавь в OBS через **Источники → Браузер**, ширина `550`, высота `160`.
6. В OBS больше **не нужно входить в Spotify**, вставлять JSON или устанавливать дополнительное приложение.

Тест интерфейса без аккаунта: [деморежим](https://witheroffic.github.io/spotify-widget-pkce/overlay.html?demo=1).

**Важное ограничение:** Worker должен быть один раз установлен в Cloudflare и связан с твоим Spotify-приложением. Пока это не сделано, главная страница не сможет сформировать работающую индивидуальную ссылку. Один только GitHub Pages не способен безопасно передать Spotify-авторизацию из Chrome в OBS.

### Настройки ссылки

На главной странице доступны частота обновления Spotify (3/5/10 секунд), время видимости, обложка и анимация. После изменения опций скопируй обновлённый адрес в OBS.

- **Перевыпустить ссылку:** старая ссылка перестанет работать; замени URL в источнике OBS.
- **Отключить Spotify:** подключение удаляется с сервера, старая ссылка перестаёт работать.
- Демо работает без Spotify: `overlay.html?demo=1`.

## Как всё устроено

```text
Spotify OAuth в Chrome → Cloudflare Worker + D1 (токены зашифрованы)
                                    │
                         отдельный ключ просмотра
                                    │
                         Ссылка → OBS Browser Source
                                    │
                         Только данные о текущем треке
```

Изображения и метаданные идут через Spotify API. Worker сохраняет Spotify access/refresh token **в зашифрованном виде** в собственной базе D1. Ссылка OBS содержит только случайный ключ просмотра — не Spotify refresh token.

## Безопасность

- Refresh token Spotify **не включается в ссылку для OBS**. Worker шифрует токены ключом `TOKEN_ENC_KEY`; секреты хранятся в Cloudflare, не в GitHub.
- **Не публикуй полную OBS-ссылку**: любой обладатель сможет видеть, какие треки сейчас играют, хотя не сможет управлять воспроизведением или получить Spotify refresh token.
- Не публикуй `PAIRING_KEY`, `TOKEN_ENC_KEY`, Spotify-токены и содержимое хранилища браузера.
- Настройки подключения сохраняются локально в браузере на главной странице. Потеря хранилища может потребовать новой авторизации.
- Режим владельца хранит **ограниченный сеансовый ключ** в localStorage; главный `PAIRING_KEY` не сохраняется. Владелец браузерного профиля или расширение с доступом к странице может создавать приглашения до отзыва или истечения 90 дней. Не включай режим владельца на чужом компьютере.
- Spotify Development Mode ограничен требованиями Spotify Premium и количеством разрешённых пользователей. Серверная архитектура **не обходит** эти ограничения.
- Веб-API Spotify не сообщает о паузе мгновенно: виджет реагирует при очередном опросе.
- Отображение музыкальных данных не даёт права транслировать аудио Spotify. Соблюдай [Spotify Developer Policy](https://developer.spotify.com/policy), включая требования атрибуции обложек и метаданных.
