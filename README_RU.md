# Spotify Widget Nutty — PKCE Edition, ноябрь 2026

Это самостоятельная **статическая веб-версия** старого Spotify Widget от nuttylmao, сохраняющая оформление: обложка, название, исполнитель, размытый фон, прогресс, время и анимация. Основа: https://github.com/nuttylmao/spotify-widget (GPL-3.0). Изменения также GPL-3.0.

**SMTC Bridge не требуется. Никаких постоянно работающих программ/локальных серверов/прокси не нужно.** Данные берутся с Spotify Web API. Но необходим Spotify Developer Client ID и **HTTPS-хостинг для файлов**. Исходные файлы нельзя просто открыть как `file://` с полноценной OAuth-авторизацией, так как Spotify требует HTTPS или разрешённый loopback HTTP redirect.

## Ограничение, которое невозможно исправить кодом

- Метод `GET /v1/me/player/currently-playing` существует и поддерживается Spotify (но может возвращать `204`, `401`, `403`, `429`).
- В Development Mode с февраля–марта 2026 владелец приложения должен иметь **Spotify Premium**. Приложения ограничены пятью разрешёнными пользователями. Авторизуемый аккаунт должен быть добавлен в User Management Spotify Developer Dashboard, если это необходимо.
- `403` из-за Premium, разрешений или правил Spotify не обойти сменой JavaScript или OAuth. Новые приложения могут иметь ограничения доступности или ошибки создания. Живой запрос без действительного Client ID и учётной записи проверить невозможно.
- Spotify Web API остаётся внешней зависимостью. Если в будущем Spotify удалит endpoint, понадобится иное решение.

## Установка без установки программ

### 1. Разместить файлы через GitHub Pages

1. Создай **публичный** репозиторий GitHub, например `spotify-widget-pkce` (не загружай туда токены или секреты).
2. Перенеси в корень репозитория **все файлы и папку `images`** из ZIP. Папку `tests` и README загружать необязательно.
3. Открой `Settings → Pages → Build and deployment → Deploy from a branch → main / (root) → Save`.
4. После публикации адрес виджета будет примерно `https://USERNAME.github.io/spotify-widget-pkce/index.html`. **USERNAME нужно заменить своим.**
5. Проверь внешний вид: открой `https://USERNAME.github.io/spotify-widget-pkce/index.html?demo=1`. Это локальная имитация песни, никаких запросов к Spotify в деморежиме нет.

Можно использовать любой другой HTTPS-статический хостинг. Серверная часть, база данных, сборка и Node.js на твоём ПК не нужны. **Не размещай сайт с чужими JavaScript-файлами на том же домене**, поскольку авторизационные данные сохраняются в localStorage этого origin.

### 2. Создать или настроить Spotify Developer App

1. Зайди на https://developer.spotify.com/dashboard под Spotify Premium аккаунтом владельца приложения.
2. Создай Web API приложение либо используй существующее разрешённое Development Mode приложение. Не удаляй существующее приложение лишь ради этой инструкции: новые приложения могут быть недоступны.
3. **Redirect URI** добавь в точности: `https://USERNAME.github.io/spotify-widget-pkce/index.html` (либо точный адрес твоего хостинга). Важно совпадение адреса, регистра, слеша и имени файла. Не нужно добавлять `?client_id=...`.
4. Убедись, что Spotify-аккаунт, под которым планируешь слушать музыку, есть в списке разрешённых пользователей приложения, если это требуется.
5. Скопируй **Client ID**, не Client Secret. Никаких секретов сервера или старых refresh token вводить не нужно.

### 3. Подключение в OBS

1. Добавь источник **«Браузер»** с URL: `https://USERNAME.github.io/spotify-widget-pkce/index.html?client_id=ТВОЙ_CLIENT_ID`.
2. Пока настраиваешь авторизацию, временно установи **ширину 800, высоту 500**, чтобы видеть кнопки.
3. Правый клик по источнику → **«Взаимодействовать»**. Нажми **«Подключить Spotify»** и разреши доступ к `user-read-currently-playing`.
4. Если вход завершился, запусти музыку в Spotify: появится виджет. Затем можешь изменить источник на **550 × 160** и расположить его поверх игры.
5. Рекомендую **снять** галочки «Выключать источник, когда он не виден» и «Обновлять браузер при переходе на сцену», чтобы избежать лишних перезапусков. Это не обязательное условие, токены сохраняются.

**Если Spotify не даёт войти из встроенного браузера OBS:** это ограничение встроенного окна, а не API. Используй перенос сеанса без отдельной программы:

1. Открой этот же URL в обычном Chrome/Firefox на ПК и авторизуйся там.
2. После авторизации открой `https://USERNAME.github.io/spotify-widget-pkce/index.html?settings=1`, нажми **«Показать подключение для переноса»** и скопируй JSON из поля.
3. В OBS открой тот же виджет, правый клик → «Взаимодействовать», вставь JSON в нижнее поле, нажми **«Импортировать подключение»**. Код обновит access token через Spotify OAuth.
4. Для обычного просмотра удали `?settings=1` из адреса (если добавлял) и установи высоту источника обратно на 160.

**Внимание:** экспорт содержит *refresh token*. Это пароль-подобный секрет для доступа к данным Spotify через твой Client ID. Не показывай его на трансляции, не отправляй никому, не вставляй в ссылку OBS, публичный репозиторий или переписку. После импорта очисти буфер обмена.

## Параметры URL

`?client_id=...` — публичный Client ID; необязателен после первого ввода и сохранения на данном устройстве/браузере.

Дополнительно через `&`:

- `duration=8` — показывать виджет только первые 8 секунд каждого нового трека (0 или отсутствие — постоянно, пока играет).
- `hideAlbumArt` — убрать квадратную обложку и оставить текстовый блок.
- `poll=3000` — интервал Spotify Web API в миллисекундах (по умолчанию 3 с, минимум 2 с, максимум 60 с). Между запросами прогресс плавно анимируется локально.
- `settings=1` — показать панель подключения/сброса авторизации.
- `demo=1` — имитация трека, для проверки дизайна без Spotify.

Пример: `https://USERNAME.github.io/spotify-widget-pkce/index.html?client_id=ТВОЙ_CLIENT_ID&duration=8&poll=15000`

## Как устроен обновлённый код

- `index.html` — сохранена HTML-структура оригинального Nutty; удалён экран прекращения поддержки.
- `style.css` — сохранена визуальная композиция оригинала и добавлена панель подключения.
- `script.js` — новая логика OAuth **Authorization Code + PKCE**, автоматическое обновление/ротация refresh token, состояния `204/401/403/429`, пауза, плавный прогресс между API-запросами, ограниченный экспоненциальный retry.
- `player-core.js` — чистые функции нормализации и тайминга, покрытые тестами.
- `images/placeholder.svg` — собственная заглушка обложки без зависимости от чужих картинок.

Ни `Client Secret`, ни `refresh_token` в URL теперь **не передаются**. Access/refresh token хранятся в `localStorage` **именно браузера, где выполнена авторизация** (Chrome и OBS имеют разное хранилище). Это не шифрование: защищай локальный профиль и не запускай недоверенный JavaScript на том же origin. Код не использует аналитику и сторонние JS CDN.

## Проверки и ограничения тестирования

- `npm test` (или команды ниже по отдельности) — 6 unit-тестов и 1 интеграционный VM-тест с подменёнными ответами Spotify. Не требует `npm install`: используется только встроенный Node.js.
- `node --test tests/core.test.mjs` — unit-тесты pure functions.
- `node --experimental-vm-modules --test tests/widget_vm.test.mjs` — проверка обновления/ротации токена, получения текущего трека и отрисовки без настоящего Spotify.
- `python tests/browser_smoke.py` — заготовлен тест UI с подменёнными Spotify OAuth/API ответами. В среде сборки запуск Chromium заблокирован административной сетевой политикой (`ERR_BLOCKED_BY_ADMINISTRATOR`); поэтому end-to-end browser test **не пройден и не заявляется как успешный**.
- Реальная авторизация и живое воспроизведение не проверены: для этого нужен **твой Spotify Premium Developer Client ID и вход в Spotify**, которых у автора ZIP нет.

## Обновление 17.11.2026: обложки и задержка паузы
- Частота опроса увеличена: по умолчанию 3 секунды (можно `?poll=2000` для 2 секунд). При ограничении Spotify `429` действует `Retry-After`; частое обновление не гарантировано.
- Прогресс корректируется после каждого ответа API; при паузе скрытие происходит после ближайшего успешного ответа, не мгновенно.
- Если ответ `currently-playing` не содержит обложки, делается дополнительный запрос `GET /albums/{id}` или `GET /tracks/{id}` с кешированием на песню. Локальные треки Spotify могут не иметь доступной обложки в Web API.
- Важно: одновременно открытые OBS и обычный браузер опрашивают API независимо, что увеличивает нагрузку на лимит запросов.
